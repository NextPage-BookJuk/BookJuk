## 1. 개요 (Overview)

BookJuk은 특정 지역을 기반으로 **일회성 오프라인 독서모임**을 손쉽게 개설·탐색·참여하고, 모임 전후로 소통과 후기(좋아요)를 통해 신뢰 있는 커뮤니티를 형성하는 웹 플랫폼입니다.
우리는 복잡한 온라인 커뮤니티보다는 **"오프라인 중심의 간편한 지역 모임 연결"**에 집중합니다.

---

## 2. 목적 (Purpose)

* 지역 기반 독서모임을 쉽게 찾고 참여할 수 있는 환경 제공
* 호스트의 체계적인 모임 운영(모집/신청/승인/상태관리) 지원
* 모임 종료 후 **좋아요(후기)**를 통한 신뢰도 축적
* **모임별 게시판**으로 모임 전후의 지속적 소통 지원

## 3. 기술 스택 (Technology Stack) + 선정 이유

> 실제 적용 버전은 프로젝트 Gradle 및 환경설정 파일 기준

### 3.1 백엔드

* **Java 17 (LTS)**: 장기 지원 버전으로 기록/성능/언어 기능(Record, Switch 개선 등) 안정성 확보
* **Spring Boot 3.3.x**: 최신 Spring 생태계 통합, 자동 설정으로 생산성↑, Observability 개선
* **Spring MVC (REST)**: 표준적인 계층 아키텍처(Controller-Service-Repository)로 유지보수 용이
* **Spring Data JPA**: CRUD 자동화, 도메인 주도 설계에 적합, 엔티티 중심 개발 생산성↑
* **QueryDSL**: 타입 세이프 동적 쿼리, 가독성/리팩토링 내구성↑ (검색/필터 조건에 효과적)
* **Validation (Jakarta Validation)**: DTO 레벨 입력값 검증으로 안정성 확보
* **Spring Security + JWT**: 세션리스 인증으로 확장성↑, API/SPA/모바일 클라이언트 연동 유리
* **Lombok**: 보일러플레이트 최소화로 개발 속도↑ (Builder/Getter 등)

**선정 이유**: 국내 백엔드 표준 스택, 커뮤니티/문서 풍부, 짧은 개발 기간에 **안정성과 생산성**을 동시에 확보.

### 3.2 프론트엔드/뷰

* **HTML5 / CSS3 / JavaScript(ES2020+)**: 범용 표준 기술, 러닝 커브 낮음, 배포/호환성 우수
* **Thymeleaf**: 서버사이드 렌더링(SSR), Spring과 자연스러운 통합, SEO/접근성에 유리

  * 선택 사유: 이번 MVP는 **빠른 구현·SSR 중심 화면 구성**이 목표. 별도의 프런트 프레임워크(React/Vue) 없이도 충분

### 3.3 데이터베이스

* **MariaDB**: MySQL 호환, 비용 효율적, 국내 운용사례 풍부
* **스키마 정책**: FK/UNIQUE 제약 생략, 인덱스 최적화 + 애플리케이션 레벨 트랜잭션 검증(중복/정합성)

  * 선택 사유: 개발 속도/유연성 우선, 동시성은 서비스 계층에서 보호(예: SELECT…FOR UPDATE, 중복 체크)

### 3.4 테스트/품질/협업

* **JUnit 5 + Spring Test**: 통합/슬라이스 테스트로 안정성 확보
* **AssertJ/Mock**: 가독성 높은 단언과 격리된 단위 테스트
* **GitHub**: PR 기반 협업(브랜치 전략, 코드리뷰, 이슈 관리)
* **Gradle**: 의존성/빌드 스크립트 단순화

**종합 선정 이유**:

* **개발 기간 15일** 내 MVP 완성도를 높이는 데 최적화
* 팀 역량/학습 곡선, 문서화/커뮤니티, 유지보수/확장성 균형

## 4. 사용자 시나리오 (User Stories)

### 4.1 호스트(Host)

* 모임을 개설한다(제목, 책, 시간, 장소(location 통합), 인원 등 입력)
* 신청자 목록을 보고 **승인/거절**한다
* 모임 정보를 **수정**한다 (PUT 방식)
* 참가자를 **내보낸다** (호스트 권한)
* 모임 상태를 **모집중→모집마감→종료/취소**로 변경한다
* 모임 게시판에 공지/안내글을 쓰고 댓글로 소통한다
* 종료 후 참여자들의 좋아요(후기)를 확인한다

### 4.2 참여자(Participant)

* 지역/장르/상태로 모임을 탐색한다(검색/정렬 포함)
* 관심 모임에 신청하고, 승인되면 참여 확정한다
* **모임 상세 주소는 참여 확정 후에만** 확인 가능
* 모임 게시판에서 **위치 정보 노출 없이** 글/댓글로 교류한다
* 종료 후 호스트/다른 참여자에게 **좋아요(1회, 취소 불가)**를 남긴다
* 마이페이지에서 내 활동(참여 모임, 받은 좋아요)을 확인한다

## 5. 기능 요구사항 (Functional Requirements)

### 5.1 회원/인증

* 회원가입: 이메일 중복 불가, 닉네임 중복 허용, 비밀번호 형식 검증(영문+숫자, 6~20자)
* 로그인/로그아웃: JWT 기반 인증, 로컬스토리지 저장, 전역 상태 관리
* 마이페이지: 프로필 수정(사진/닉네임/자기소개/선호장르), 내가 만든/참여한 모임, 남긴·받은 좋아요 조회

### 5.2 모임 관리(호스트)

* 모임 개설: 제목/소개/책(제목·저자)/장르/시간/주소(location 통합)/최대 인원/이미지 입력
* 모임 수정: **PUT 방식**으로 전체 정보 업데이트
* 신청자 관리: 신청 목록 확인 및 **PATCH 방식**으로 승인(APPROVE)/거절(REJECT) 처리, 정원 초과 승인 제한
* 참가자 제거: **DELETE 방식**으로 내보내기
* 상태 변경: 모집중(RECRUITING) → 모집마감(FULL) → 종료(COMPLETED)/취소(CANCELLED)

### 5.3 모임 탐색/신청(참여자)

* 모임 목록: 카드형, 페이지네이션, 최신/마감임박/인기 정렬
* 필터/검색: 지역, 장르, 상태(RECRUITING/FULL/COMPLETED/CANCELLED)
* 모임 상세: 일반 사용자는 기본 위치 정보만 표시, **상세 주소는 참여자/호스트만 확인 가능**
* 참여 신청/취소: 모집 마감 전 신청 가능, 신청 직후 **짧은 시간(예: 1분) 중복 신청 방지**
* 신청 상태: PENDING(승인대기) → APPROVED(승인) / REJECTED(거절)

### 5.4 모임 게시판

* 접근 권한: **호스트 또는 승인된 참여자**만 글/댓글 작성 가능, 비참여자는 읽기 전용
* 게시글: 작성/수정/삭제, **위치 정보 제거**, 작성자/시간 정보만 표시
* 댓글: 작성/수정/삭제, **댓글 카운트 실시간 업데이트**

### 5.5 후기(좋아요)

* 조건: 모임이 **종료(COMPLETED)** 상태이고, 본인을 제외한 대상에게만 가능
* 제약: **1회만 가능, 취소 불가, 중복 불가**
* 조회: 모임 상세 및 마이페이지에서 확인

## 6. 비기능 요구사항 (Non-functional Requirements)

* **성능**: 평균 응답 1.5초 이내
* **보안**:
  - JWT 토큰 기반 인증, 로컬스토리지 저장
  - **상세 주소 정보 접근 제어** (참여자/호스트만)
  - **API 권한 검증** (401/403 에러 처리)
  - BCrypt 비밀번호 해싱, XSS 방지를 위한 HTML 이스케이프
  - 민감정보 마스킹/로그 금지
* **신뢰성/정합성**: 정원 초과/중복 신청 방지를 트랜잭션으로 보장, 삭제 시 참조 데이터 정리 규칙 적용
* **사용성**: 반응형 UI, 접근성 고려(시맨틱 HTML5, 라벨/대체텍스트)
* **운영**: 회원가입/모임 생성/에러 로깅, 감사 추적(누가 언제 무엇을)

## 8. API 명세 (API Specifications)

### 8.1 인증 API
- `POST /api/auth/login` - 로그인
- `POST /api/auth/logout` - 로그아웃
- `GET /api/auth/me` - 현재 사용자 정보

### 8.2 모임 API
- `GET /api/meetings` - 모임 목록 조회
- `POST /api/meetings` - 모임 생성
- `GET /api/meetings/{id}` - 모임 상세 조회
- `PUT /api/meetings/{id}` - 모임 수정
- `POST /api/meetings/{id}/apply` - 모임 신청
- `GET /api/meetings/{id}/participants` - 참가자 목록
- `PATCH /api/meetings/{id}/participants/{userId}` - 참가자 승인/거절
- `DELETE /api/meetings/{id}/participants/{userId}` - 참가자 내보내기

### 8.3 게시판 API
- `GET /api/meetings/{id}/posts` - 게시글 목록
- `POST /api/meetings/{id}/posts` - 게시글 작성
- `GET /api/meetings/{id}/posts/{postId}` - 게시글 상세
- `GET /api/meetings/{id}/posts/{postId}/comments` - 댓글 목록
- `POST /api/meetings/{id}/posts/{postId}/comments` - 댓글 작성

## 10. 상세 비즈니스 로직 (Business Logic Details)

### 10.1 모임 신청/승인 프로세스
1. 사용자가 모임 신청 → 상태: PENDING
2. 호스트에게 알림 (UI상 표시)
3. 호스트가 승인/거절 결정 → 상태: APPROVED/REJECTED
4. 승인 시 참가자 목록에 추가, 상세 주소 열람 권한 부여
5. 정원 초과 시 신청 불가

### 10.2 중복 방지 로직
- 동일 모임 중복 신청 방지
- 동일 사용자 좋아요 중복 방지
- 트랜잭션 레벨에서 동시성 제어

### 10.3 권한 관리
- **호스트**: 모임 수정, 참가자 관리, 모임 취소, 상세 주소 확인
- **참가자**: 게시글 작성, 댓글 작성, 상세 주소 확인
- **게스트**: 모임 조회만 가능, 기본 위치 정보만 확인

## 11. 예외 처리 (Error Handling)

### 11.1 클라이언트 에러 (4xx)
- `400`: 잘못된 요청 (유효성 검증 실패)
- `401`: 인증 실패 (로그인 필요)
- `403`: 권한 없음 (호스트 전용 기능 등)
- `404`: 리소스 없음 (존재하지 않는 모임 등)

### 11.2 서버 에러 (5xx)
- `500`: 내부 서버 오류

### 11.3 에러 응답 형식
```json
{
  "error": "VALIDATION_FAILED",
  "message": "입력값이 올바르지 않습니다",
  "details": ["제목은 필수입니다", "최대 인원은 2명 이상이어야 합니다"]
}
```

## 12. 보안 정책 (Security Policies)

### 12.1 인증/인가
- JWT 토큰 유효기간: 24시간
- 토큰 저장: 로컬스토리지
- 세션 관리: Stateless (서버에 세션 저장 안함)

### 12.2 입력값 검증
- XSS 방지: HTML 태그 이스케이프
- SQL Injection 방지: PreparedStatement 사용
- 파일 업로드: 현재 미구현 (URL 입력 방식)

### 12.3 개인정보 보호
- 비밀번호: BCrypt 해싱
- 민감정보 로깅 금지
- 이메일 마스킹 (일부 문자 * 처리)

## 13. 운영 정책 (Operational Policies)

## 17. 용어 정의 (Glossary)

* **모임(Meeting)**: 오프라인 독서 이벤트 단위
* **호스트(Host)**: 모임 개설·운영 권한자
* **참여자(Participant)**: 모임에 신청/승인되어 활동하는 사용자
* **후기(Review)**: 종료된 모임 후 남기는 좋아요(하트)
* **모임 게시판(Post/Comment)**: 해당 모임 참여자 전용 소통 공간
* **상세 주소**: 참여자/호스트만 확인 가능한 구체적인 모임 장소
